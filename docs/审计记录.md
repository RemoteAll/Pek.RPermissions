### 发现与处置

| # | 级别 | 发现 | 处置 |
|---|---|---|---|
| 1 | 中 | **吊销名单可被"换拼写"绕过**：验签用容错 base64 解码签名段（接受 `=` 填充、空白、标准字母表），而吊销名单以**原文** SHA-256 为键——同一令牌的等价拼写验签通过、却查不到吊销记录（登出失效）。任意令牌都可追加 `=` 构造等价变体（约 74% 还天然含 `-`/`_` 可直接替换）。 | ① `Jwt::validate_at` 增加**规范形态校验**：签名段解码后必须与 `base64_url_no_pad` 重编码完全一致，否则"签名验证失败"（与 C# 字符串精确比较口径一致）；② `TokenRevoker` 键改为**规范化令牌**（仅签名段：容错解码 → URL 安全无填充重编码；非三段/解码失败按原文兜底）——双保险。 |
| 2 | 低-中 | **与 C# 行为差异（同源）**：C# `TryDecode` 对签名段是 `enc(...).ToUrlBase64() == ts[2]` 字符串精确比较（填充/空白/字母表变体一律拒绝），Rust 此前容错接受——"同一令牌在 C# 被拒、在 Rust 被收"的行为分叉。 | 随 #1 一并对齐（C# 黄金样本 + 互通脚本双向复核通过）。 |
| 3 | 低 | **空密钥接受**：`HS256:`（空密钥）可构造 `Jwt` 并签发/验签空密钥令牌；C# 对空 Secret 明确拒绝（decode 返回"未设置密钥"、encode 抛异常）。 | `Jwt::new` 构造时拒绝空密钥（错误消息注明对齐 C#「未设置密钥」）。 |
| 4 | 低 | `JwtOptions` 由 `derive(Debug)` 输出**密钥原文**（任何 `{:?}`/日志即泄密）。 | 改手写 `Debug`：`secret` 固定输出 `***`。 |
| 5 | 低 | `encode_at` 的 `now + expire_minutes * 60` 极端入参可溢出（debug 恐慌 / release 回绕）。 | 改 `saturating_add` / `saturating_mul`。 |

### 观察项（维持现状，均有据）

- `exp` 缺失 → 不做过期检查（C# 为构造时"默认 2 小时窗口"；两者均偏宽松，模块文档已注明"仅当声明存在"）；
- 不校验 `iss`/`aud`（与 C# `TryDecode` 一致——C# 也不校验）；
- C# 验签会**读取 header 算法**（HS384/HS512 亦注册）；Rust 固定 HMAC-SHA256、不读 header——**Rust 更安全**（天然规避 `alg=none` 类攻击），文档已注明；
- C# 签名比对为字符串相等（非常量时间）；Rust 用 `fixed_time_eq` **常量时间**——Rust 更优；
- `revoke.rs` 锁中毒时 `is_revoked` 返回 false（fail-open）——锁内无 panic 路径，实际不可触发，维持；
- rustfmt：仓库基线本身不符当前默认配置（历史代码多处 chain_width 差异）——**不执行全量 `cargo fmt`**（防大 diff），新增代码与现文件风格保持一致。
