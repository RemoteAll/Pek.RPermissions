## 1. 项目是什么

与 C# 端（Pek.Permissions / DHDeploy 使用的 NewLife `JwtBuilder`）**字节级互通**的 JWT 公共库（crate `pek-rpermissions`）：

| 模块 | 内容 |
|---|---|
| `jwt` | HS256 编解码：`JwtOptions` / `Jwt::{encode, encode_with, encode_at, validate, validate_at}`（`*_at` 供测试注入时间）；C# 黄金样本固化在单测 |
| `claims` | 标准 claims（`sub` / `name` / `from` / `clientType`）构造与解析（`Claims::admin/app`） |
| `revoke` | 内存吊销名单（登出即失效；重启清空）；键=规范化令牌（签名段解码→URL 安全无填充重编码） |

**定位**：凡"令牌需要与 C# 生态互认"的 Rust 项目统一引入本库、勿逐仓复制（2026-10-10 用户提议建立；从 Pek.RCard 项目内实现下沉为独立公共库）。

## 4. 关键设计（改动前必读）

1. **互通口径**（对照本地 DH.NCore `Web/JwtBuilder.cs` 与 `IO/IOHelper.cs`）：
   - header `{"alg":"HS256"}`（紧凑、无 `typ`）；payload 紧凑 JSON 且键序不限（验证按令牌原文验签）；
   - `exp` / `iat` 为 **Unix 秒**；`now > exp` → 过期、`now < nbf` → 未生效（仅当声明存在；与 C# 一致）；
   - 密钥格式「算法:密钥」：`Split(':')` 取第二段（与 C# `Split(':')[1]` 一致；**密钥不要含冒号**）；
   - C# 验签为 `enc(...).ToUrlBase64() == ts[2]` **字符串精确比较**（ToUrlBase64 = 去填充 + `+/`→`-_`）。
2. **签名段"规范形态"校验**（2026-10-11 审计）：Rust 端签名段必须与 `base64_url_no_pad(签名字节)` 完全一致，否则"签名验证失败"——既对齐 C#，也保证吊销名单键稳定（见下条）。
3. **吊销名单键=规范化令牌**：仅规范化签名段（其余两段参与 HMAC 原文，改动即验签失败）；非三段/解码失败按原文兜底。同一令牌的 `=` / 空白变体共享一条吊销记录。
4. **与 C# 的有意差异（更安全，勿"对着改"）**：只按固定 HMAC-SHA256 验签、不读 header 算法（C# 会读 header 选择算法）；签名比较为常量时间（C# 为字符串相等）。
5. **空密钥**：构造时拒绝（`HS256:` 无效；对齐 C#「未设置密钥」）；`JwtOptions` 的 `Debug` 对密钥输出 `***`。

## 5. 坑与红线（已踩过）

- **仓库基线不符当前 rustfmt 默认**（历史 chain_width 等差异）——**勿全量 `cargo fmt`**（会制造大 diff）；新增代码随文件现有风格。
- 中文 `.ps1` 必须 **UTF-8 with BOM**（PS 5.1 按 GBK 读无 BOM 会报语法错误；`tools/continuity` 脚本已处理，编辑后需重写 BOM）。
- 互通验证依赖 `Pek.RCard/tools/jwt-interop.ps1`（内部构建 C# 工具 `tools/csharp/JwtInterop`，引用本地 DH.NCore 源码工程）——C# 侧相关工程路径变动时同步检查。
- 验证时间相关行为一律用 `*_at`（注入时间），勿依赖真实系统时钟。

## 6. 版本与发布

- 版本在 `Cargo.toml`（当前 **0.1.0**）；库本体无打包流程；消费方以 path 依赖（`pek-rpermissions = { path = "../Pek.RPermissions" }`）。
- 如未来对外发布（私服 / git 依赖），先补 `repository` 元数据与 LICENSE 文件（当前 `license = "MIT"` 未附文件）。
